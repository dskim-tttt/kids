# 긴 여행을 지리 탐험으로 만드는 기능 검토

아래는 제안이며, 아직 앱에 구현하지 않았다. 초기 사용자는 보호자와 함께 이동하는 5~10세로 가정한다.
목표는 긴 화면 체류보다 ‘화면에서 한 가지 발견 → 창밖 확인 → 가족과 대화’다.

| 기능 | 예시 | 교육 효과 | 데이터·구현 | 우선순위 |
|---|---|---|---|---|
| 도시 여행 도장 | ‘수원시에 왔어요!’ 도장과 도시 이름 읽기 | 지명 인지, 이동 순서 이해 | 현 도시 조회 재사용, 2~3회 연속 확인·경계 진동 방지, 보호자 동의 시 기기 내 도시명만 저장 | 1 |
| 창밖 탐험 카드 | ‘강을 찾을 수 있나요?’, ‘산과 언덕은 어떻게 다를까요?’ | 실제 지형 관찰과 가족 대화 | 초기에는 일반 카드, 발견 여부는 아이가 직접 선택. GPS만으로 특정 지형을 보았다고 판정하지 않음 | 1 |
| 도시 한 줄 이야기 | ‘이 도시 이름은 어디서 왔을까?’ | 지명과 역사 연결 | 출처·이용허락을 확인한 소규모 한국어 편집 콘텐츠부터. 검증되지 않은 실시간 AI 지명 유래 생성 금지 | 2 |
| 지나온 도시 줄 잇기 | ‘서울 → 성남 → 용인’ 도시 카드 | 이동 경로와 공간 순서 | 시·군·구 표시 단위 통일, 같은 도시 중복 최소화. 상세 좌표·시각 기록 불필요 | 2 |
| 방향 탐험 | ‘지금은 남쪽으로 가고 있어요’ | 방위 개념 | GPS 이동 방위, 저속·정지 때 표시 보류. 휴대폰이 향한 방향과 이동 방향은 다름 | 2 |
| 강·산·터널 근처 이야기 | ‘곧 한강을 건널 수 있어요’ | 지형과 위치 연결 | 지도 POI·경로 데이터, 출처·라이선스, 터널 GPS 단절 처리 필요. 직선거리만으로 통과 단정 금지 | 3 |
| 거리 감각 놀이 | ‘10km는 학교 운동장 몇 바퀴일까?’ | 거리·시간 감각 | 비교 대상 크기를 명시. 예상 도착 시간은 목적지와 실제 경로 정보 확보 후 | 3 |

## 첫 출시 권장 범위

속도계 + 현 도시 + 일반 창밖 탐험 카드. 그다음 도시 도장.
도시 경계는 Geocoder 결과가 변할 수 있으므로 연속 관측·대기시간을 적용한다.
GPS가 끊겼을 때 새 도장을 주지 않고 ‘위치를 다시 찾는 중’으로 표시한다.
터널 길이·주변 산 이름·도시 유래는 외부 콘텐츠 없이는 추측해서 제공하지 않는다.

## 아이 중심 설계

- 점수는 높은 속도, 더 먼 이동, 더 많은 위치 제공과 연결하지 않는다.
- 경쟁 순위, 광고, 채팅, 로그인, 이동 알림은 초기 범위에서 제외한다.
- 1회 카드 10~20초 내, 큰 글씨와 선택적 음성. 소리·음성은 기본 끔, 보호자가 켠다.
- 자동 도시 이벤트는 화면이 보이는 동안에만; 이벤트를 위해 백그라운드 추적하지 않는다.
- 기본은 여행 기록 미저장. 도장 저장을 도입하면 보호자 설정, 기기 내 저장, 여행 삭제 기능을 함께 제공한다.
- 위치 서비스를 통한 역지오코딩에는 기기/서비스 제공자의 네트워크 처리가 있을 수 있음을 정확히 설명한다.

## 평가 방법

대표 연령 5~7세, 8~10세와 보호자에게 짧은 탑승 테스트를 한다.
카드를 보고 창밖을 관찰했는지, 지명 하나를 기억하는지, 보호자가 대화를 시작하기 쉬운지 확인한다.
화면 사용시간을 성공 지표로 삼지 않는다. 초기에는 분석 SDK 없이 보호자 인터뷰로 확인한다.
